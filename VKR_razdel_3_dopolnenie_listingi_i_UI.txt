Для регистрации «пустой» карточки сценария (только наименование и описание) используется эндпоинт POST /scenarios. Листинг 3.8 – Реализация записи сценария в персистентное хранилище (файл crud.py)

def create_scenario(db: Session, scenario_in: schemas.ScenarioCreate) -> models.Scenario:
    existing = db.query(models.Scenario).filter(
        models.Scenario.name == scenario_in.name
    ).first()
    if existing is not None:
        raise ValueError("Сценарий с таким названием уже существует")

    scenario = models.Scenario(
        name=scenario_in.name,
        description=scenario_in.description,
    )
    db.add(scenario)
    db.commit()
    db.refresh(scenario)
    return scenario

Пояснение к листингу 3.8. Выполняется проверка отсутствия дубликата по имени, создаётся объект ORM, фиксируется транзакция и возвращается актуальное состояние строки для ответа API.

3.8 Создание сценария с графом регламента в одном JSON-запросе

Полное описание дерева решений передаётся структурой ScenarioWithNodesCreate: список узлов с временными строковыми ключами и ссылками next_node_key на следующий узел. Сервер преобразует ключи в числовые идентификаторы записей Node и Answer в базе данных.

Пояснение к листингу 3.9. Маршрут делегирует разбор графа функции create_scenario_with_nodes; ошибки целостности (неизвестный корень, битая ссылка на узел) преобразуются в ответ 400.

Листинг 3.10 – Сопоставление ключей узлов и создание ответов (фрагмент crud.py)

    key_to_node: dict[str, models.Node] = {}
    for node_in in scenario_in.nodes:
        node = models.Node(
            scenario_id=scenario.id,
            question=node_in.question,
            is_final=node_in.is_final,
            final_action=node_in.final_action,
        )
        db.add(node)
        db.flush()
        key_to_node[node_in.key] = node

    root_node = key_to_node.get(scenario_in.root_node_key)
    if root_node is None:
        raise ValueError("Root node key not found in nodes list")
    scenario.root_node_id = root_node.id
    db.flush()

    for node_in in scenario_in.nodes:
        current_node = key_to_node[node_in.key]
        for answer_in in node_in.answers:
            next_node_id = None
            if answer_in.next_node_key:
                next_node = key_to_node.get(answer_in.next_node_key)
                if next_node is None:
                    raise ValueError(
                        f"Next node key '{answer_in.next_node_key}' not found"
                    )
                next_node_id = next_node.id
            db.add(
                models.Answer(
                    node_id=current_node.id,
                    text=answer_in.text,
                    next_node_id=next_node_id,
                )
            )

Пояснение к листингу 3.10. Двухпроходная схема: сначала создаются все узлы и словарь key_to_node, затем для сценария задаётся root_node_id, после чего для каждого ответа вычисляется next_node_id по ключу целевого узла и записывается связь в таблице answers.
